# 影片製作輸出流程

只要任務跟影片有關（新做、修改、重剪、上字幕、重新輸出），開工前先照以下規則規劃；派 subagent 做影片時，把這些規則整段寫進它的 prompt。**多場景的影片一律一個場景派一個 agent 並行製作**（見「加快交件」）。

- **分場景輸出＋快取**：每個場景各自輸出成一段，輸入沒變的場景直接沿用上一版，最後再接成整片。改一段只重做那一段，不整支重跑。
- **先截圖、後影片**：每輪先給使用者每個場景一張截圖（contact sheet），版面與文字確認後才輸出影片。
- **先預覽、確認後才輸出正式版**：每輪修改只交截圖和即時預覽頁（配音、音效接成一條音軌，跟 `window.seek(t)` 同步），**不輸出 mp4，連低畫質預覽影片也不出**（使用者 2026-10-24 定）；使用者明確說要輸出才出。要出低畫質時用直式 540×960、橫式 960×540、15 fps；說「輸出正式版」才出正式解析度（直式 1080×1920、橫式 1920×1080，30 fps）。
- **開工前先給完整分鏡腳本**（使用者 2026-10-24 定）：派任何場景 agent 之前，先在對話裡貼出分鏡腳本，每一場都要寫出用哪些照片或畫面、運鏡和轉場，以及**每一句完整台詞**（字幕原文逐句列出），不可以只列「旁白重點」或摘要。台詞改版時也要重貼完整版。
- **使用者給的台詞照原文用**（使用者 2026-10-24 定）：使用者寫了旁白原文時，字幕和配音逐字照原文，只在使用者指定的地方修改；不要自行潤飾成口語、合併或刪句。原文只能在標點或語意停頓處拆行，拆行不能改字。數字照寫（例如「3~4 家」），念法放在念稿的發音替換裡處理。
- **滿版照片不切出螢幕、不變形**（使用者 2026-10-24 定）：照片「滿版」指的是等比例縮放到貼滿畫面的一邊（contain），整張照片都要在畫面內，不裁切、不拉伸。其餘空間用同一張照片的模糊版補滿（使用者 2026-10-24 最後定案：預覽和輸出都只用模糊補邊）。AI outpainting 延伸背景實測（越南短片 22 組）約一半生出新人臉、補完招牌字或接縫斷層，入選的使用者看了也覺得不自然，所以不再預設做；使用者主動要求才做，且原照片像素要原樣蓋回、先做樣本確認。只有台詞講到要看某處時，才推近裁切。
- **轉場要有運鏡，而且全片統一**（使用者 2026-10-24 定）：場與場之間、同一批人換照片，都用像攝影機移動的運鏡轉場（推軌、平移、推近接續），不只是淡入淡出。全片用同一種運鏡語言，只有運鏡邏輯跟台詞有關時才例外（例如講「推薦我上去」就往上搖到屋頂）。新的轉場先做示範頁給使用者挑。
- **能預覽就預覽，影片和縮圖都一樣**（使用者 2026-10-24 定）：縮圖、封面也比照影片，先在即時預覽頁給使用者看（直式、橫式各一個網址，可以直接切換），不先輸出 JPG。改版就在預覽頁上改，使用者確認後才輸出正式檔。
- **正式版影片、縮圖、字幕檔先輸出到 Remotion 專案，再備份到 Windows 下載資料夾**：見 `video-shared-rules`（兩種模式共用）。
- **第 0 格要是封面**：見 `video-shared-rules`（兩種模式共用）。
- **字幕預覽不燒入**：預覽時由播放器疊字幕（srt/vtt），改字幕不必重輸出；定稿才燒進影片。
- **修改一次給齊再開工**：進行中追加修改容易讓前面白做，收齊一輪意見再派工。

## 加快交件（2026-10-24 颱風火柴人短片檢討）

那一輪做了一個多小時，慢在四件事：一個 agent 從頭到尾依序做、配音反覆重產（ElevenLabs 5 次、Gemini 4 次，每次都要轉寫比對）、中途改了好幾次方向、草稿階段檢查做太細。之後照下面做：

- **順序是先畫面和字幕，預覽確認過才做聲音**（使用者 2026-10-24 定）：先做畫面，台詞以字幕或泡泡呈現，排好時間軸，交即時預覽頁讓使用者確認劇情、節奏和台詞。確認後才產配音和配樂，配音配合已確認的時間軸，只微調秒數。畫面還沒定就做配音，劇情一改，配音就白做了。
- **一律多 agent 並行，幾個場景就派幾個 agent**（使用者 2026-10-24 定，比照 Remotion 一個場景一個 composition 的做法）：主迴圈先定好共用的東西（畫布、安全區、角色元件、字型、時間軸介面，例如每個場景一支 `comp/scenes/s<N>.js`，匯出 `build(root)` 和 `duration`），然後同一則訊息裡一次派出每個場景各一個背景 agent，各自只改自己的場景檔，各自出截圖。每個版本的配音、配樂也各派一個 agent，各自寫自己的檔案（例：`comp/plan_A.js`、`audio/mix_A.wav`）。最後由主迴圈整合、驗收。共用檔（角色元件、comp.html、預覽頁）只由主迴圈或指定的一個 agent 改，不讓兩個 agent 同時改同一個檔案；場景要改共用元件時，回報給主迴圈統一改。
- **CPU 負載上限**（使用者 2026-10-26）：本機 4 核心，1 分鐘負載不可超過 4。算圖一律 nice 19、限 2 核心、JOBS=1、MAXLOAD 3.0；不用 Blender 算圖（只做建模匯出）。發現負載過重就不併行：算圖、Blender、大量截圖、全碟搜尋改成一次只跑一個，多 agent 也要排隊，不同時算圖。
- **草稿階段不重試、不細查**：配音只產一次就交給使用者聽，念錯等使用者指出再修；檢查只做到頁面能載入（沒有 404 和 pageerror）、沒有缺字、畫面沒被切到。疊圖比對、逐格檢查、同步誤差量測留到正式版前再做。
- **機械性的工作用 sonnet**：混音、排時間軸、複製檔案、改設定都派 sonnet；角色造型、畫面判斷、驗收才用 opus。
- **意見收齊再派一輪**：agent 做到一半時收到的補充，要等它手上那一步做完才會處理，會讓前面的工作白做。可以先問清楚的就先問，進行中有新意見先記下來，下一輪一起給。
- **沿用現成的工具**：`~/projects/Remotion/projects/typhoon-abv-reel/` 已經有火柴人角色元件（`comp/chars.js`）、Gemini 和 ElevenLabs 的 TTS 腳本、依停頓切句、混音（`audio/mix.py`）、可切版本的有聲預覽頁、whisper 轉寫 venv。新的動畫短片直接複製這套開工。

## 動畫劇情片的演出（2026-10-24 三國呂布片使用者意見）

用立繪、地圖或火柴人演故事時，照下面做：

- **人物講到才出場**：旁白講到誰（例如「呂布盟友袁紹」講到袁紹），那個人才出場。畫面上只留這一句有提到、或正在互動的人，不要一開場就把所有人擺出來。旁白逐字出現，出場時間對準關鍵字。
- **出場要有方向感**：從所屬地盤或陣營的方向滑入，退場也一樣，不要只用淡入淡出。
- **重點時刻要演成真的互動**：例如遞禮、反水、怒罵、結盟、背刺。人物要有表情（怒、驚、汗、得意、心虛），也要有實際的動作：靠近、遞東西、翻旗、衝出來罵、被震開。不要只放一張字卡。
- **情緒用畫的、演的，不寫成情緒字**（使用者 2026-10-24：「表情情緒一律用畫的演的，不是直白寫在人物旁邊……我是說狂喜、疑惑這類直白文字」）：情緒靠表情圖（同一張立繪用 AI 只改表情）、光影、姿勢和動作表現。畫面上不准出現「狂喜」「疑惑」「得意」「心虛」這類直接寫出情緒的字。可以保留的有：問號、驚嘆號、汗滴、青筋這類符號（畫成跟畫風一致的質感），說明身分或物品的小字（例如流浪軍、友軍、大禮、擾敵、先攻、猛將、矯詔），人物名字條，以及原文裡的台詞。
- **定裝一律給預覽網頁**（使用者 2026-10-25）：人物定裝、畫風試做都要做成可在 Windows 打開的預覽網頁（WSL IP），角色可旋轉／切換姿勢或並排檢視，不能只給一張 PNG。
- **改表情或特效，都先給使用者預覽**（使用者 2026-10-24 定）：新做或改版的表情、特效、立繪表情變體，先放在示範頁（每個效果單獨播一次）或對照圖給使用者看，確認後才套用到全片。示範頁網址要用 Windows 打得開的位址（WSL IP，不要用 localhost）。
- **寫實風格，不要可愛風**（使用者原話：「閃閃發光、得意的笑、反覆跳動人像都太生硬又智障，應該寫實一點，帶點惡意狡詐」）：這類題材不用閃光、星星、彈跳、上下跳、漫畫符號（青筋、汗滴、驚嘆號）。情緒用光影表現，例如半臉陰影、冷暖側光、暗角，再加上緩慢推近和單次有重量的動作。道具要有寫實質感，動作要慢、帶停頓，像古裝劇的陰謀戲。
- **計謀、牌、物品要演成動作，不放生硬的字卡**：故事裡出現的計謀（例如矯詔、擾敵、鐵壁）、牌（承諾卡、手牌、先攻令牌）和物品（禮物、繩子、城旗），都要有人拿著它做動作，對象也要有反應。例如：擾敵是探子或煙霧飛進敵陣，把對方的牌打散；矯詔是展開聖旨、蓋印飛出去壓住對手。字卡只拿來輔助標示名稱，不能當主角。
- **攻打、結盟、反水、勝敗都要看得懂**：
  - 攻打：箭頭或兵鋒從 A 地盤打進 B 地盤
  - 結盟：兩人靠攏，出現盟印
  - 反水：旗子實際翻面、換顏色
  - 勝敗：勝者放大加光，敗者變灰、下沉
- **地盤太小就推鏡頭**：用平順的推近和平移，放大到看得清楚，演完再拉回。立繪和字幕框不跟著縮放。
- **場景之間要接得上**：下一場的開頭先擺出上一場結尾的狀態（勢力分布、還在場的人），再接著變化。或者上一場最後 0.5～0.8 秒把自己的元素收掉。不可以硬切到空白地圖、讓所有東西在一格內消失。
- **同一個人全片用同一張臉**：立繪要先處理乾淨（去背或羽化，拿掉原片的色塊殘影），不要這場用素材裁圖、下一場換成另一個版本。
- **不加故事沒有的東西**：數字、台詞、情節都以原文為準。例如原文只說「削減一波很大戰力」，就不能自己編戰力 18 → 7。
- **分工**：先由一個 opus agent 升級共用元件（鏡頭、依台詞出場、表情和互動特效）並寫導演稿（每一框的鏡頭、人物、互動、勢力變化），再派各場景 agent 照導演稿並行實作。

## 迷因／搞笑短片的配音

- **不用 ElevenLabs eleven_v3 加預設聲音**：那種腔調適合教學和宣傳片，放在迷因片裡太平淡。改用 Gemini TTS（可以用文字描述語氣，例如「台灣口音、朋友之間嗆人、尖酸惡毒、起伏大、語速快」）。
- **edge-tts 一律不用**（使用者 2026-10-24：「太機械」）：任何影片都不用。
- **連在一起的詞要真的一口氣講**：念稿不要加逗號（寫成「藥到難除一拖再拖只好繼續拖」），風格提示寫「一口氣、不換氣、越講越快」；產出後句中不能有超過 0.08 秒的停頓，有就剪掉，必要時整句用 atempo 加快。
- **節奏要快**：總長大約 25～28 秒，台詞之間不留空，結尾停 1.5 秒。連續的幾個詞要一口氣講完（例如「藥到難除、一拖再拖、只好繼續拖」），畫面跟著每個詞快速切換。
- **同一個角色的台詞用同一個聲音、一次產生**，聽起來才像同一個人一路講到底。
- **配樂可以用白癡搞笑風**：自己合成，或用授權明確的免版權曲並附上出處。

## 工具選擇與預覽方式

- **產品示範影片優先用「題庫短影音」這套做法（使用者 2026-10-07 指定，不用 Remotion）**：Playwright 錄真實畫面成影格序列 → HTML＋GSAP 合成（`comp/`，`window.seek(t)` 決定性渲染）→ 分場景快取渲染（`render.mjs --scenes/--all/--draft`）→ `stills.mjs` 出截圖總覽 → `preview_server.mjs` 本機即時預覽（含配音、字幕開關）→ `final_build.sh` 燒字幕＋混音 → `deliver.sh` 交付。範本工作區：`~/projects/Remotion/projects/math-question-bank-reel/`（說明在其 `README_render.md`），新影片複製這套工具另開資料夾，橫式就把畫布改成 1920×1080。Remotion 只在使用者指定時才用。
- **預覽用即時預覽，不輸出影片**：改字幕、時間、標示、鏡頭位置時，用本機即時預覽頁（`preview_server.mjs`）讓使用者直接播放、拖時間軸，不要每改一次就輸出 mp4。只有使用者確認後才輸出。
- **錄影最花時間，錄之前先定案**：開錄前先給分鏡表（每個鏡頭：頁面與資料、操作步驟、運鏡、標示、字幕、是否寫入測試資料），再用真實頁面試跑、截關鍵畫面給使用者確認，才正式錄影，避免反覆重錄。

## 配音與字幕節奏（2026-10 題庫短影音定案做法）

- **語速預設 1.0**：ElevenLabs `eleven_v3` 不吃 `voice_settings.speed`；真要變速只能後製 `atempo`（保持音高），整條做一次，不逐句做。使用者偏好 1.0。
- **念錯只重產有錯的場次**（使用者 2026-10-24 定）：低 stability 每次整份重產都會隨機出現新念錯，不要整份重來。保留念對的場次，只重產有錯的場次（eleven_v3 不支援 previous_text／next_text，帶了會回 400；只送該場念稿，seed 與設定不變，接回前把響度對齊前後場），用 whisper 挑念對的那次，在換場停頓處接回原音軌。
- **整份旁白一次請求**：用 `/with-timestamps`、`language_code: "zh"`、固定 `seed`、固定 `voice_settings`，所有句子音色語氣一致；整條一次 loudnorm（-16 LUFS）。
- **發音替換只改念稿、不改字幕**：發音表見 `video-shared-rules`（兩種模式共用）。
- **場景內不切句**：保留 TTS 自然換氣與停頓（逗號約 0.13–0.25 秒、句尾約 0.35–0.7 秒）；只在場景交界、原音停頓裡切開，切口加約 6 毫秒淡入淡出；場景尾巴 0.12 秒，不另加開頭延遲（參考 grill-me reel）。把一段語音切成一句一句再插人工空白會有頓點、像麥克風斷斷續續。
- **畫面跟著聲音走**（在畫面和字幕預覽確認之後的配音階段適用）：配音決定場景長度的細部微調；沒有旁白的空檔用加速（上限約 2–2.5 倍）或剪掉靜止畫面（剪在畫面停穩處，不剪掉因果）吸收，不停格、不讓畫面空等。
- **字幕一次一行**：只顯示正在念的那一行，長句在標點處拆成多行輪流顯示，不並排、不疊兩行；時間取自逐字時間戳，短於 0.3 秒的空檔延到下一句避免閃爍。字幕文字＝旁白原文（不是替換後的念稿）。
- **情境式講法**：用「我幫某某老師做…」「老師遇到…就…」這類接案情境敘述，講畫面上正在發生的動作，不用「不是…而是…」句型，不講沒做出來的功能當成已上線。

## 真實錄影、自然接續、少後製（產品示範的核心原則）

目標是讓觀眾覺得「這是真的在操作」，不是後製拼出來的畫面。

- **一律真實錄影**：產品功能用真實系統畫面錄（瀏覽器自動化或螢幕錄影），滑鼠、點擊、頁面載入、捲動都是真的操作。不要把畫面截圖裁下來，重新拼成設計過的對照版面、分割窗格或並排卡片。
- **自然接續**：同一個功能盡量一鏡到底，頁面之間用真實的點擊、換頁銜接，不要硬切跳到另一個畫面。必須剪接時，剪在動作完成、畫面停穩的地方，不要剪掉操作的因果（點了什麼 → 出現什麼）。
- **用鏡頭強調，不用拼版**：要看清楚某一處，就在真實畫面上平順地放大、平移推近（Screen Studio 式的運鏡），看完再拉回。放大要慢、要平順，讓觀眾跟得上是在看哪裡。
- **清楚靠錄影品質**：字太小就提高錄影解析度（deviceScaleFactor 2–3）、加大瀏覽器縮放，或用介面本身的縮放功能，不要靠後製把裁圖放大、重排。
- **前後對照也在真實畫面裡做**：例如真實介面本來就是左右並排（原卷 ↔ 辨識結果），就推近那個真實版面；修改前後就拍同一個欄位改之前、改之後。
- **疊加只限輕量**：只加框、箭頭、貼在真實元素上的小標籤、字幕；不加大面積色塊、假視窗、重新設計的面板。
- **尚未開發的功能**：在真實頁面上用同風格元件模擬，並清楚標示「開發中」；不要另外畫一套假介面。
- **畫面不可被切到**：重點介面（頁面、面板、卡片、題目、按鈕）要完整入鏡，左右上下邊緣不能截掉內容；鏡頭只在真實頁面範圍內推近、平移。
- **截圖／裁圖要完整**：影片畫面、縮圖、卡片裡用到的任何系統截圖或裁圖，都要把要呈現的元素完整框進去（整張卡片、整道題目含選項與附圖、整個按鈕或面板），不可裁在文字、公式、圖形或邊框中間（例如只露出圖形框上緣一小條）。放不下就整體縮小或換構圖，不要硬切；交件前用全尺寸逐張確認裁切邊緣。
- **不可出現亂碼**：公式、數學符號、中文都要渲染完成才錄（等 MathJax／MathLive／字型載入完），不能露出 LaTeX 原始碼、半渲染畫面或缺字方框。
- **標示不可蓋住內容**：框、標籤、箭頭放在元素旁邊，不疊在要讀的文字或數字上。
- **交件前逐格檢查**：每個場景至少抽開頭、中間、結尾三格，用全解析度確認沒有被切到、亂碼、重疊、字太小；有問題先修再交，並在回報裡誠實列出還沒解決的。
- **縮圖／封面例外**：縮圖不必硬截一格畫面，可以把真實系統畫面的元素（高解析裁圖、真實卡片、按鈕）重新排成好看的版面，例如「匯入考卷 → AI 辨識結果」前後對照；但素材必須來自真實畫面，文字取自旁白，不可出現錯誤狀態（例如故意製造的錯誤值）或「開發中」。
- **資料要前後一致**：整支影片盡量跟著同一筆資料走（例如同一道題目），每一段看到的內容彼此對得上，避免東拼西湊。

## 3D 動畫人物規則（2026-10-25～26 越南短片使用者意見）

- **做法**：Blender（MPFB/MakeHuman CC0）只用來建模、匯出 glb；算圖用 three.js 即時算（卡通 3 階著色＋外輪廓＋有色輪廓光），不用 Blender 逐格算圖。3D 交 Windows 內顯、照片場景分給本機和 Hetzner（`tools/dist_render.sh`）。畫風可參考《Clone Wars》但不照抄，不出現光劍、戰甲、槍。
- **定裝一律給預覽網頁**：可旋轉、切姿勢、臉部特寫，每個角色旁放照片裁切對照。
- **人物照真實照片做**：臉型、髮型、髮色、膚色、衣著都對照片；「我」用亞洲臉型（偏瘦、雙髮旋）。沒照片的角色做中性一般人，不刻意強調性別。
- **一定要看得到正常的臉**：眉、眼（眼白＋瞳孔）、鼻、嘴清楚，臉部要補光，輪廓線不畫進臉內。表情自然，不要空洞眼。
- **動作要自然**：
  - 走路：手臂自然下垂、與腳反向前後擺，不要一直往前舉著。
  - 上樓梯：一階一階踩實，重心前傾，手扶欄杆，不滑行不浮空；情緒（期待、忐忑）用停頓、回頭、深呼吸表現，時間要夠長（約 3～5 秒），空檔補旁白，不要無聲。
  - 拿手機：雙手握住兩側、手指收攏、拇指打字；不要單手、不要五指張開。
  - 群體場景每個人都要參與（湊過來看、指、互看笑、拍肩、喝酒），手要有小動作（放桌上、托腮、比手勢、拿杯、鼓掌），動作時間錯開，不能呆站。
- **道具與場景要符合真實情境**：桌面朝上、人圍桌；啤酒用有把手玻璃杯裝啤酒；手機平放桌上互相推給對方看，雙方都要打字（用 ChatGPT 翻譯對話）。門要有門框、門板、門把，看得出是門。背景乾淨，不要散落的英文霓虹字或無意義裝飾。
- **地點和劇情要對**：例如搭話在民宿門口（還沒進去）。換場跟著劇情走：第一站還沒開始路跑就不放喝酒換場；路跑換場要乾杯、陸續換新陌生人。
- **對話內容**：手機上的對話一開始就顯示內容，不用長段「• • •」；內容太短可以補符合情境的寒暄（例如互問來自哪裡），補的內容先給使用者確認。
- **排版**：手機特寫和人物用上下分割，不互相遮擋，整支手機完整入鏡。
- **錯誤版本留存**：被否決的段落切出來存 `output/<片名>/errors/` 當錯誤素材。
